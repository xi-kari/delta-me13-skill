**诊断：**

- 症：首页白屏＋入口脚本解析失败。
- 病（候选，未确诊）：某个 JS 请求拿回的是 HTML（多半是 `index.html` 或 404 页面），浏览器把 `<!DOCTYPE html>` 的第一个 `<` 当作 JS 解析而报错。这是从报错文本推出的推断，强度较高；要等检查 1／2 看到响应体以 `<` 开头、`Content-Type: text/html`，才算观察确认。
- 附带推断：这种报错形态更像经典 `<script>` 加载（webpack／CRA／Vue CLI 一类产物，或懒加载 chunk）；如果是 Vite 默认的 `type="module"` 入口，拿到 HTML 时浏览器通常会先报 MIME 类型错误。以你的实际构建工具为准。
- 基线：dev 与生产的差别正好是“构建后的资源路径＋静态服务器回退规则＋缓存”，dev 服务器三者都不经过，所以“本地正常、线上白屏”与上面的病相符。剩下要解释的是：为什么 JS 地址会落到 HTML 上。竞争解释如下：

| 候选病因 | 区分性预测 | 证伪条件 |
|---|---|---|
| ① 资源基础路径与部署位置不符（Vite `base`、webpack `output.publicPath`、CRA `homepage`／`PUBLIC_URL`、Vue CLI `publicPath`） | 报错请求的 URL 缺少或多出子路径前缀；所有用户、无痕窗口都复现；本地按同一子路径托管产物也复现 | 请求 URL 与服务器上文件的实际路径完全一致 |
| ② 新旧版本错配（浏览器／CDN 缓存了旧 `index.html`，引用的旧 hash 文件已被新部署删除） | 请求的文件名 hash 在服务器当前产物里不存在；无痕或强刷后可能恢复；只有部分用户复现 | 请求的文件在服务器当前产物中存在，且无痕窗口同样白屏 |
| ③ 产物不完整（资源目录漏传、传错目录，或上传顺序导致 HTML 先于 JS 生效） | 服务器上对应文件不存在，而本地构建目录里存在 | 服务器上文件完整存在 |
| ④ 服务器回退规则把静态资源也改写成 `index.html`（如 SPA 的 `try_files … /index.html` 覆盖了资源路径，或 location 匹配顺序问题） | 文件确实在服务器磁盘上，但直接请求它仍返回 HTML | 直接请求该文件返回 JS 内容与 JS 类型 |

①–④ 可以同时成立（例如 ① 造成 404，再被 ④ 的回退规则包成 HTML）。按检查 1→3 的顺序一次验证一个。

**处方 A·最小修复：** 确诊后只改命中的那一处，不动别的。

- 修改：① 把基础路径改成实际部署路径，重新构建、重新部署；② 刷新 CDN 缓存（至少 `index.html`）；③ 重新完整上传构建产物；④ 让资源路径命中真实文件、不存在时返回 404（只改这一条规则）。
- 代价：改动面最小，通常一次构建＋一次部署即可；不防复发。
- 风险：① 改基础路径会影响所有资源和路由前缀，深层路由要一并验证；④ 改规则时要确认前端路由刷新仍回退到 `index.html`。
- 回退：保留当前构建产物与服务器配置副本，可原样恢复。如需先止血，可以回到上一个可用版本——这属于回滚，需要你对具体版本单独确认后才执行，我不会代做。
- 验收：无痕窗口与普通窗口首页均正常渲染；控制台无该 SyntaxError；`index.html` 引用的每个 JS 都返回 200 且 `Content-Type` 为 JavaScript 类型；深层路由直接刷新仍正常。

**处方 B·根治方案：** 在 A 之外，把交付链改成“出错就显式报错，不再把 HTML 当 JS 发出去”。

- 修改：
  1. 缓存分层：`index.html` 设 `Cache-Control: no-cache`；带 hash 的静态资源设长缓存＋`immutable`。
  2. 资源路径不走 SPA 回退：资源目录下不存在的文件直接 404，只有页面路由回退到 `index.html`。
  3. 部署顺序与保留：先上传新资源，最后替换 `index.html`；旧版本资源保留一个过渡期，避免还持有旧 HTML 的用户请求落空。
  4. 部署后冒烟检查：抓取线上 `index.html`，解析出全部脚本地址，逐个确认 200＋JavaScript 类型，不通过就阻断发布或告警。
  5. 可选：响应头加 `X-Content-Type-Options: nosniff`，让同类问题直接表现为 MIME 拒绝，而不是难懂的 SyntaxError。
- 代价：涉及服务器／CDN 配置与 CI 流水线，改动面和验证量明显大于 A；保留旧资源会占用存储。
- 风险：缓存规则配错可能让用户长期拿到旧版或降低命中率；冒烟检查需要持续维护。
- 回退：每项配置独立提交、独立回退。
- 验收：A 的全部验收项；另做一次新旧版本交替发布演练，持有旧 `index.html` 的会话不白屏；故意请求不存在的资源时返回 404 而不是 HTML。
- 边界：第 1–4 项属于环境／构建／CI 范围。若选 B，建议拆成新单，请负责环境与 CI 的丹恒承办；本病历只给清单。

**暂不处理：** 受影响用户的首页持续不可用；若是 ②，部分用户会随缓存过期自行恢复、另一部分不会，表现为“时好时坏”，更难定位；下一次部署还可能再次触发同类问题。
